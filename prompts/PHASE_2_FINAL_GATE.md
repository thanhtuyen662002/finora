## 3. Restore current Supabase Proxy identity pattern

The approved Phase 0 foundation used the current Supabase SSR `getClaims()` request-boundary pattern.

Current official Supabase SSR guidance prefers `getClaims()` for protecting pages/data and requires session refresh to happen immediately after client construction.

Unless current official documentation gives a concrete reason not to, restore the proxy identity check to `supabase.auth.getClaims()` rather than using `getUser()` solely for route protection.

Do not use `getSession()` as authorization proof.

No unrelated logic may be inserted between `createServerClient(...)` and the identity/session refresh call.
